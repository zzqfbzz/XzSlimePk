# XzPk V3 —— 史莱姆区块扫描器（图形界面版）

在《我的世界》里划定一个大范围，程序找出其中 **8×8 区块（=128×128 格）窗口**内
史莱姆区块**最多**（适合建史莱姆农场）和**最少**的位置，各保留 topK 条。
判定公式与真实游戏一致（见下文）。

## 使用（唯一入口 = 图形界面）

```bat
v3\gui.bat          # 双击：编译并启动界面
v3\selftest.bat     # 双击：运行内置自检（可选）
```

界面里**所有输入都需手动填写，没有隐藏默认值**：

| 控件 | 说明 |
|---|---|
| 计算模式 | `sliding(滑动窗口, 推荐)` = 范围内每个区块都可作窗口左上角，找任意摆放最优；`grid(从角点铺格)` = 从范围左上角起每隔 windowSize 铺互不重叠的格子 |
| 坐标单位 | `方块坐标(游戏F3)`（默认推荐，自动 ÷16）或 `区块坐标` |
| 世界种子 | 游戏内 `/seed` 显示的值，必填 |
| 范围 | 两个角点：起点 (x,z) ~ 终点 (x,z)，按所选单位填，必填 |
| 窗口大小 | 区块数，如 `8`（单个玩家可加载的最大区域 = 8×8 区块 = 128×128 格），必填 |
| 输出条数 | 最多/最少各保留多少条（如 `100`），必填 |

点“开始扫描”后后台多线程计算，结果输出在下方文本区（每行一条，可直接复制）；
扫描完成后点 **“导出为 TXT”**，会把完整报告（**含种子与坐标**）直接保存到
程序当前目录，文件名 `史莱姆区块结果_种子<seed>.txt`（UTF-8 纯文本）。

## 关键语义

- **窗口只需左上角锚点区块在范围内**，8×8 窗口可向右/向下**溢出**范围边缘，
  超出部分照常统计满 64 格（例：方块范围 0~100 → 锚点 0,16,…,96 共 7 个）。
- **坐标换算**：方块坐标 ÷16 向下取整得区块坐标（负数也正确）。范围填两个角点，
  窗口永远按区块数填。
- **输出行格式**：`数量|x,z=世界方块坐标|X,Z=起点区块坐标|WxW|占比`
  - x,z：窗口起点区块西北角的方块坐标；X,Z：窗口起点区块坐标
  - 例：`18|x,z=-144,-320|X,Z=-9,-20|8x8|28.1%`
- “最多的”按 数量降序 → 距原点近→远 → Z升 → X升；“最少的”按 数量升序 →
  距原点近→远 → Z升 → X升。
- 结果**只保留最多/最少各 topK 条**（有界堆逐条比较插入），不保存全部窗口，
  扫描上亿候选窗口也只需 1~2 秒（8 线程）。

## 判定公式（与 Minecraft 官方一致）

依据 [Minecraft Wiki](https://minecraft.wiki/w/Slime)，各坐标项先按 **32 位 int 运算**
（溢出回绕）再与种子相加，最后异或掩码：

```java
hash = seed + (int)(chunkX*chunkX*0x4c1906) + (int)(chunkX*0x5ac0db)
             + (int)(chunkZ*chunkZ)*0x4307a7L + (int)(chunkZ*0x5f24f);
hash ^= 0x3ad8025fL;
new Random(hash).nextInt(10) == 0   → 史莱姆区块（概率 10%）
```

注意：旧版 `slimepk.java` 用**全程 long** 写法，区块坐标超过约 ±20 即与真实游戏不一致
（例：种子 `-2870327070709450083`，NW 方块 `(93696,-192)` = 区块 X5856~5863 Z-12~-5：
long 写法数 24，官方应为 **11**）。V3 已用官方写法并把该窗口作为自检回归用例。

## 目录结构

```
v3/
├─ gui.bat              # 编译并启动图形界面
├─ selftest.bat         # 编译并运行内置自检
└─ src/xzpk/
   ├─ Gui.java          # 图形界面（输入框 + 开始按钮 + 输出区）
   ├─ Config.java       # 内存配置 Builder 与校验（GUI 直连，无文件/无隐藏默认）
   ├─ SlimeChunk.java   # 史莱姆区块判定（官方 int 语义）
   ├─ GridScanner.java  # grid 模式（从角点铺格，多线程）
   ├─ SlidingScanner.java # sliding 模式（滑动窗口 + 滑窗优化，多线程分片）
   ├─ TopKCollector.java # 有界 Top-K 收集器（内存 O(K)，逐条比较插入）
   ├─ ResultItem.java   # 一条结果 + 排序规则
   ├─ ScanResult.java   # 扫描汇总
   ├─ ProgressBar.java  # 进度条（后台扫描可用）
   ├─ Output.java       # 结果格式化报告
   └─ Selftest.java     # 无框架自检
```

## 自检覆盖

- 判定公式与 Wiki 官方写法：4 万随机坐标对照 + 用户回归窗口（=11）
- 坐标单位换算边界（方块→区块，负数向下取整）
- grid / sliding vs 暴力直接数（含负坐标、溢出、skip=2、非对称范围等）
- 两次运行结果确定性
